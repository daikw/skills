# Handoff Create - 引き継ぎドキュメント生成

中断した作業を再開するための補足資料を HANDOFF.md として書き出す。
次のセッションや別のエージェント（Claude Code / Codex / 人間）が、STATE.md と必要な参照先を読んで作業を再開できるようにする。

## 作業状態の記録

現在の依頼とプロジェクトの記録方針を確認する。継続作業の現在地は STATE.md にまとめ、HANDOFF.md には再開に必要な補足を残す。既存の保存先・形式がある場合はそれを使い、指定がなければ STATE.md はリポジトリ直下（Git がない場所では cwd）に置く。

STATE.md には目標、現在地、未完了事項、障害、次の一手、最終確認時点と根拠への参照を残す。検証済み・未検証・承認待ちを区別し、他の作業状態を保全する。既存の STATE.md や設計文書にある内容は、HANDOFF.md へ複製せず参照先を書く。

引き継ぐ作業が完了している場合は、必要な判断・知見・検証結果を保存して STATE.md を更新し、不要になった当該 HANDOFF.md をプロジェクトの削除・退避方針に従って取り除く。他の未完了作業を含むファイルは丸ごと消さない。更新と整理の結果を報告して終了し、以下の生成手順には進まない。完了報告など別の成果物を明示的に求められた場合は、その依頼に従う。

引き継ぎ文書を書き終えたことを、引き継ぐ作業の完了とはみなさない。

## モードと出力先

`$ARGUMENTS` を解釈する:

- 先頭トークンが `quick` → **quick モード**（下記の最小テンプレート）。残りは出力先パスとして扱う
- それ以外（省略含む） → **full モード**（デフォルト、下記のフルテンプレート）。`$ARGUMENTS` 全体を出力先パスとして扱う
- 出力先パス省略時は `./HANDOFF.md`

**モードの目安**: 変更ファイル数が数個・意思決定も単純なら quick で十分。複数の意思決定・Failed Approaches・他エージェントへの正式な引き継ぎが要るなら full を使う。

## 手順

### 1. コンテキスト収集

**quick モード**は最低限のみ:
- `git status --short` と `git branch --show-current`
- 現在のタスクリスト（あれば）

**full モード**は以下を自動的に調べる（すべて必須ではない。該当するものだけ集める）:

- **Git 状態**: `git status`, `git diff --stat`, `git log --oneline -10`, 現在のブランチ
- **変更ファイル一覧**: 未コミットの変更、新規ファイル
- **TodoWrite の状態**: 現在のタスクリスト（あれば）
- **エラー/失敗**: 直近で失敗したコマンドやテスト結果
- **環境**: 使用中のランタイム/フレームワークのバージョン

### 2. 作業状態を更新し、HANDOFF.md を生成

先に STATE.md を現在の状態に更新する。以下のテンプレートのうち、STATE.md や他の文書に記録済みの項目には、その参照先を書く。実際の状態と照合していない記録を確認済みとして扱わず、秘密値を文書へ含めない。

**quick モードのテンプレート**:

```markdown
# HANDOFF (Quick)

_Generated: {datetime}_

## Goal

STATE.md の目標・完了条件への参照。

## Done

- STATE.md の確認済み事項への参照。

## Next

- STATE.md の次の一手を実行するための補足手順。記録済みの内容は参照先を書く。

## State

- 現在地、ブランチ、未コミット変更、検証状況は STATE.md を参照。
- Notes: 再開に必要な補足、またはその参照先。
```

**full モードのテンプレート**: 以下のテンプレートに沿って書く。セクションが不要な場合は省略してよい。

```markdown
# HANDOFF

_Generated: {datetime}_
_Session: ${CLAUDE_SESSION_ID}_

## Goal

STATE.md の目標・完了条件への参照。

## Completed

- STATE.md の確認済み事項と、検証結果の保存先への参照。

## Not Yet Done

- STATE.md の未完了事項への参照。

## Failed Approaches

> 次のエージェントが同じ失敗を繰り返さないための記録。

- **やったこと**: 何を試したか
  - **結果**: なぜ失敗したか
  - **教訓**: 次に試すべきこと / 避けるべきこと

## Key Decisions

| 意思決定 | 選択肢 | 理由 |
|----------|--------|------|
| 例: ORM選定 | Drizzle | 型安全 + 軽量、Prisma は重すぎた |

## Current State

- 現在地、ブランチ、未コミット変更、検証状況、既知のエラーは STATE.md を参照。
- 再開に必要な詳細がある場合は、秘密値を除いたログの保存先を記載。

## Code Context

次のエージェントがすぐ使えるよう、重要なシグネチャやパスを記載。

- **エントリポイント**: `src/index.ts`
- **主要な型/インターフェース**:
  ```typescript
  // 例: 重要な型定義をコピペ
  ```
- **API レスポンス例**:
  ```json
  // 例: 外部APIのレスポンス形式
  ```

## Resume Instructions

1. このファイルを読む
2. `{具体的な再開コマンド}`
3. 期待結果: `{何が起これば正常}`

## Setup Required

- [ ] 必要な環境変数: `FOO_API_KEY`
- [ ] 依存インストール: `npm install`
- [ ] その他の前提条件

## Warnings

- 注意すべき罠やハマりポイント
```

### 3. 出力後の確認

生成した HANDOFF.md の行数と主要セクションを報告する。

## 知識の保存先との使い分け

STATE.md は継続作業の現在地、HANDOFF.md は中断した作業の再開に必要な補足を記録する。後でも必要な判断や知見は、設計文書や Issue など、プロジェクトが定める記録先へ残す。auto-memory を更新する場合は、その環境で利用可能な更新口と明示された許可に従う。引き継ぎ文書の作成を、commit・push や外部への共有の許可とはみなさない。
