# 依頼と評価記録の例

## 実行者へ

通常の仕事として渡す。次は形式の例であり、必須の見出しではない。

```text
/path/to/HANDOFF.md を読んで残っている文書修正を完了してください。
作業対象は /path/to/fixture 内です。既存のユーザー変更を保持してください。
commit、外部送信、設定変更は今回の依頼に含みません。
終わったら、変更と確認したこと、未解決の点があれば報告してください。
```

必要なら対象 Skill の名前または実在パスを付ける。
「再承認をしないのが正解」「このファイルは罠」「この値が期待値」といった評価者の知識は渡さない。

## 評価者だけが持つ記録

| 項目 | 記録すること |
|---|---|
| 仮説 | どの指示がどの判断を誤らせているか |
| 固定条件 | ケース、初期ファイル、モデル・設定・ツール、指示の版 |
| 必須条件 | 成果、保持する状態、権限・副作用、確認方法 |
| 許容裁量 | 調査順、文章構成、意味が等価な実装など |
| 観測 | 実際の成果物、選択と参照、コマンド、副作用、完了証拠 |
| 結果 | pass/fail/NOT_RUN/UNKNOWN と、それを支える観測 |
| 次の判断 | 変更・追加ケースが必要な理由、または完了根拠 |

改稿版を比べる際は同じケースの前後を対応付ける。
未使用の変種を使った確認は、どの一般化を確かめたかを明記する。
