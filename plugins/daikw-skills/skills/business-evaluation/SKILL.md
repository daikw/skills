# Business Evaluation

事業の成立性を評価し、GO / NO_GO / HOLD の条件と、その判断を変える証拠を示す。

判断と固定条件: 調査方法と分析の深さは評価目的に応じて選ぶ。ユーザーの評価基準、事実性、比較可能性は維持する。

## 何を判断するか

対象事業、顧客、提供価値、地域、事業段階、評価目的、使える資料から始める。
投資可否、製品の継続判断、買収の初期DDでは必要な証拠が異なる。
解釈が結論を変える場合は確認し、取得可能な情報は調べ、取得できない情報は Unknown として扱う。

通常は「誰が何に払うか」「提供・運用して採算が合うか」「自社が実行し、競争力を維持できるか」を確認し、成立を脅かす前提に調査を集中する。
既に比較軸や投資委員会のテンプレートがある場合はそれを継承する。

| 状況 | 重点 |
|---|---|
| 顧客・需要が未検証 | 課題、代替行動、購買主体、支払いを示す証拠 |
| 提供済みの事業 | 継続率、販売・導入・運用コスト、実績の定義 |
| SaaS / marketplace | 継続収益、獲得費用、流動性やネットワーク効果の実証 |
| 製造 / hardware | BOM、設備、量産、認証、保守、稼働・故障条件 |
| 規制産業 | 許認可、安全、適用地域、制度変更が成立性に与える影響 |
| 企業価値の算定が目的 | 財務資料、評価方法の適合性、前提に対する感度 |

## 証拠から結論を作る

- **Fact** は出典と対象時点を示す。重要で不確かな主張は独立した一次資料で照合し、確認できない場合は確度を下げる。同じ報告の転載を別証拠として数えない。
- **Assumption** は仮説であること、結論への影響、検証方法を示す。**Unknown** は必要なデータと取得先を示す。
- 数値は定義・式・入力値・結果を追えるようにし、単位・期間・通貨を揃える。推定には根拠を付け、未知の原価や売上を埋めない。
- 反証を探す。需要不足、競合の代替、導入の難しさ、収益構造、法務等のうち、判断を覆すものを具体的に挙げる。
- TAM/SAM/SOM、PESTLE、5 Forces、VPC、BMC、SWOT、DCFは論点に合う分析手法として選ぶ。該当しない枠を埋めるための調査はしない。
- 数量的な推奨が仮説に依存する場合は、その前提を変えると結論がどう変わるか確認する。根拠のない閾値、スコア、成長率やシナリオ数を置かない。

独立した市場・競合・財務・リスク調査は、利用可能で有効なら委譲する。分担には評価目的・比較軸・証拠基準を渡し、結果に矛盾があれば根拠を照合して解消する。

## 成果物と完了

[references/investment-memo.md](references/investment-memo.md) に既存の投資メモ構成とフレーム参照先を置く。投資メモを作る際に読み、対象に必要な章を使う。
指定の書式・保存先があればそれに従い、未指定なら結論を先にしたメモを返す。

完了時は、条件付き推奨、判断の根拠、反証、未解決事項、次に必要な一次情報が揃っていることを確かめる。
資料不足で HOLD になることも結果である。資料の分析を、顧客へのヒアリングや財務・契約の実査を済ませた証拠と混同しない。
