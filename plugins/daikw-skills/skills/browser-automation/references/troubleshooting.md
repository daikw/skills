# ブラウザ操作の復旧

実際のエラーに対応する項目だけ確認する。変更・停止の対象を特定し、他のセッションを維持する。

| 観測 | 切り分けと対応 |
|---|---|
| Browser is already in use | profileの所有者と使用中セッションを確認する。既存contextを利用するか、自分用の隔離contextを作る。共有profileのlockを消して強行しない |
| 起動引数が反映されない | 有効なMCP設定元と該当serverの引数を確認する。別の設定ファイルを推測で上書きしない |
| 残存プロセスが疑わしい | 自分が起動したPIDと所有するセッションを照合する。終了が必要な対象だけをツールのclose/disconnectまたは通常の終了操作で止める |
| ログイン画面になる | 対象アカウント、対象URL、認証状態の読み込み、失効を確認し、本人のログインで更新する |
| 要素が見つからない | 表示状態、ページ遷移、iframe、ロード完了を観測し直す。ツールの最新refまたは文書化済みのlocatorを使う |
| clickが反映されない | overlay、disabled、画面外、非同期処理を確認する。再clickの前に既に操作が成立していないか調べる |
| screenshotが不完全 | viewport/fullPage、対象要素、保存先、形式を利用ツールの仕様に照らして確認する |

プロセス名で一括終了するコマンドは使わない。帰属を確認できないプロセスや既存のユーザーtabは保持する。
プロセスや設定の調査でも、引数・環境変数・認証ファイルに秘密が含まれ得るため全文を表示しない。

Playwright MCPの一般的な確認には `browser_snapshot`、状態待ちには `browser_wait_for`、画像には `browser_take_screenshot` を使える。
公開されているtool schemaに従い、別ブラウザツールにこれらの名前や引数を流用しない。
失敗が続くときは同じ操作を繰り返さず、最後に確認できた状態と不足する能力を示す。
