# E2E検証

受入条件のうち、ブラウザで確認する必要がある振る舞いをシナリオにする。
repoの既存E2E・起動手順・test dataを使い、一般的な例からサービスやportを推測して新設しない。

## 例: カテゴリフィルタ

1. 対象環境を確認し、カテゴリを選ぶ前の一覧を観測する。
2. 現在の画面から特定したカテゴリ操作を行う。
3. 一覧が指定カテゴリに変わり、対象外が含まれないことを確認する。
4. 値はDOM等で、視覚的なレイアウトは画像で検証する。

この順序は状態依存の操作の例。画面が変わってrefが古くなったら観測し直す。
動的コンテンツは表示・通信等の実条件で待つ。

## 証拠と副作用

- 既存のfixtureやテスト用アカウントを使い、対象環境を本番と混同しない。
- データ作成や外部送信を含むシナリオは、許可と後片付けを先に確かめる。
- 成功判定はclickの成功でなく、受入条件の状態変化に置く。
- 要求やrepo方針が指定する正常・異常・境界・再実行時の動作を確認する。
- URL、対象version、シナリオ、結果、必要な画像・ログ、未確認項目を残す。

単独のunit/integrationでは確認できない統合や画面挙動に重点を置く。
既存方針や明示要求があるE2Eを、unit testがあることだけで省略しない。
