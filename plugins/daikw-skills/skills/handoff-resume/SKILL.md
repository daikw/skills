# 引き継ぎからの再開

現在の依頼と引き継ぎから残る成果を復元し、関連する変化を確かめ、認可済みの次作業を実行する。
読み込みやタスクリスト作成だけで、再開の依頼を完了扱いにしない。

## 現状と引き継ぎを照合する

指定された文書を読む。省略された場合は cwd の HANDOFF.md、既知の docs 配下の順に候補を探す。
広い履歴検索は必要なときだけ行い、複数候補から目的を特定できない場合は確認する。
特定の見出し名や生成ツールを必須にせず、目的、完了済み、未完了、失敗した方法、承認と制約を読み取る。

記録された commit・branch・対象ファイル・必要な外部状態と現状を比較する。
Git のある場所では status、関連 diff、記録以降の log を確認し、Git がない場所ではファイルを直接照合する。
文書の古さだけで期限切れと判定しない。外部状態は作業上必要なら現在の証拠を取る。

## 差分をどう扱うか

- 無関係な追加や完了済み作業: 状態を更新して説明し、既存変更を保全して先へ進む。
- 依頼に沿う関連変更: 引き継ぎの手順を現在の実装・仕様に合わせる。
- 目的・仕様・権限・対象の同一性を変える衝突: 依存する変更を止め、決定が必要な点を確認する。独立した許可済み作業は進めてよい。
- 危険な古いコマンドや現行規則との矛盾: 現在の指示を優先し、何が古く何を採用したかを示す。

drift があるという理由だけで、取得済みの許可を聞き直さない。未実行の検証を成功扱いせず、過去の失敗を無条件に繰り返さない。

## 作業と完了

目的、再開位置、判断を変える drift を短く伝えて実行する。
複数の作業がある場合は利用可能なタスク管理手段を使うが、特定のツールが無いことを再開の blocker にしない。
受入条件に対応する検証まで実行し、結果・残る未完了・必要な判断を報告する。
新しい handoff や memory の作成は依頼・プロジェクト方針・利用可能な更新口に従う。過去の記録を勝手に上書きしない。
