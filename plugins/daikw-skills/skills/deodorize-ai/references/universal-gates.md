# Universal gates — 全ルート共通（捏造 F 系 + 残骸 R 系）

どの種別の入力にも必ず適用する。F 系は integrity 層（最優先）、R 系は surface 層だが判定が決定論的（誤検出がほぼない）。

## F 系: 捏造された具体性（integrity）

全カテゴリ中で唯一、severity が一貫して高く、検出条件が完全に反証可能（実在するか、しないか）。他の tell がスタイルの問題に還元されうるのに対し、これだけは客観的な誤り。**surface tell を 1 つでも検出した文書では、F 系を必ず走らせる。**

### F-1 幻の出典（Phantom Citation） — critical

- 検出: 引用されている文献・DOI・ISBN・URL に、実在が確認できないものが 1 件以上あるか？
- なぜ: LLM は引用を検索せず、訓練分布上もっともらしい著者・誌名・年の組み合わせを生成する。捏造引用の 2/3 は実在文献と重複ゼロの完全な発明。
- 修正: DOI / URL を機械的に確認する（WebFetch）。確認できないものは UNKNOWN として残件報告し、勝手に削除も温存もしない。
- 出典: https://arxiv.org/pdf/2603.03299

### F-2 匿名権威への帰属 — critical

- 検出: 「業界レポートによれば」「専門家は指摘する」「観測筋は」のような、名前のない情報源への帰属があるか？
- なぜ: 主張に信頼性の見た目を付ける最も安価な手段。少数意見を広範な合意に見せる副作用を伴う。
- 修正: 帰属先を実名にするか、帰属を外して主張自体の要否を判定する。

### F-3 出典なき数値 — critical

- 検出: パーセンテージ・金額・件数・順位が出典なしで書かれているか？
- なぜ: 具体的な数値は説得力の記号として機能するため、文脈に「合う」桁の数字を生成してしまう。
- 修正: 出典を付けられない数値は削除する（丸めて残すのではなく消す）。数字の穴は正直に空ける（「計測予定」「要確認」のラベル付き）。

### F-4 存在しない対象への参照 — critical

- 検出: 文書が参照する関数・クラス・API・サービス・設定項目のうち、実在しないものがあるか？
- なぜ: 命名規則から「あるべきもの」を補完する。実例: curl に届いた AI 生成脆弱性報告は存在しない関数のデバッグ情報とでっち上げのメモリアドレスを含んでいた。
- 修正: 参照先を Grep / Read で実体と突き合わせる。確認できない参照は UNKNOWN として明示する。
- 出典: https://www.bleepingcomputer.com/news/security/curl-ending-bug-bounty-program-after-flood-of-ai-slop-reports/

### F-5 URL 汚染と未使用参照 — major

- 検出: (a) 引用 URL にトラッキングパラメータ（`utm_source=` 等）が付いているか？ (b) 参照リストに宣言されているが本文から一度も参照されない文献があるか？
- なぜ: 訓練データ中の共有リンクの再生 / 参照整合の未追跡。それ自体は無害だが F-1 の強い共起指標。
- 修正: URL を正規化し、未使用参照を削除する。

## R 系: ハーネス残骸・チャット残骸（surface・決定論的）

検出が機械的で曖昧さがない。**R 系が残っている文書は誰も読み返していない証拠**なので、検出したら F 系の監査を優先的に強化する。

### R-1 引用トークンの残骸 — critical（確定的）

- 検出: 以下の文字列が出現するか？

| 由来 | 文字列 |
|---|---|
| ChatGPT | `contentReference`, `oaicite`, `oai_citation`, `turn0search`, `attributableIndex`, 単独の `+1` |
| Gemini | `[cite: 1]`, `[span_1](start_span)` |
| Grok | `grok_card`, `grok_render_citation_card_json` |
| DeepSeek | 隅付き括弧【】、ダガー † |
| Perplexity | `attached_file`, `ppl-ai-file-upload` |

- 修正: 機械的に除去。そのうえで文書全体の通読と F 系監査を行う。

### R-2 応答の枕詞の残存 — critical（確定的）

- 検出: `Certainly! Here is...` / `As an AI language model` / `As of my last update` が本文に含まれるか？
- 実例: Elsevier 誌に `Certainly, here is a possible introduction for your topic` で始まる論文が査読を通過して掲載され、後に撤回された。
- 修正: 除去し、文書全体を人間が通読したか疑う。

### R-3 協調的コミュニケーションの漏出 — critical

- 検出: 文書（記事・仕様書・レポート）の中に、読者ではなく依頼者に向けた発話があるか？（「他にお手伝いできることがあれば」「Let's explore」「as we can see」）
- 修正: 削除。

### R-4 プレースホルダの置き去り — critical

- 検出: `[TODO]` / `[Your Name]` / `{{project_name}}` / 「〜を記載してください」がそのまま残っているか？
- 修正: 実データで埋めるか削除。

### R-5 組版済み引用符の混入 — minor

- 検出: プレーンテキスト・コード近傍でカーリークォート（“ ” ‘ ’）が使われているか？
- 注意: 人間の執筆環境でも自動変換で発生する。単独では指摘しない。**コードブロック内の混入のみ major**（動かないコードを生む）。
