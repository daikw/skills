# autoresearchへの引き継ぎ

この形式は、外側のmodify → verify → keep/discardループが既に合意されており、その一回の試行を委譲する場合に使う。
外側ループが未定なら、成果と評価方法を確認して通常のmissionか探索かを判断する。
ML用語、数値目標、repo-wideという範囲だけを切替条件にしない。

## 引き継ぐもの

- 今回変える仮説と範囲
- 固定する入力・実行環境・評価契約
- 一回の試行に対するverifierと成功/失敗の記録
- 外側がkeep/discardを判断するための証拠
- 合意済みの資源制約と、実行不能時の報告先・方法

既存の結果ファイルやlogがある場合はそれを使う。
なければ必要な結果の保存先を決める。汎用の状態ファイルを一律に増やさない。

## 終了

一回の試行とその検証が終わったら結果を外側へ返す。
検証の失敗は今回の結果として保存し、全体目標を達成したとは書かない。
全体の収束、次の試行、採用・破棄は外側ループの契約に従う。
新しい試行を無断で開始しない。

外側ループの設計を依頼された場合は、利用可能なautoresearchの計画用skillを案内できる。
`/autoresearch:plan` 等の呼び出し名は導入されたpluginで確かめる。未導入の機能が自動実行されると約束しない。
